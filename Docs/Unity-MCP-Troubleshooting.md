# CoplayDev Unity MCP: диагностика и надёжная работа

Repository: https://github.com/CoplayDev/unity-mcp

## 1. Архитектура подключения

Cline (MCP client) -> Unity MCP server -> Unity Editor bridge/plugin -> active Unity project.

Успешное соединение не означает, что модель правильно вызывает каждый инструмент. Отдельно проверяются транспорт, доступные инструменты, схема аргументов, выполнение в редакторе и read-back результата.

## 2. Первичные проверки

1. В Unity открой `Window -> MCP for Unity`; убедись, что сервер запущен и статус показывает Connected.
2. Убедись, что открыт нужный проект и активна нужная сцена.
3. В Cline открой MCP Servers и проверь, что Unity MCP подключён без ошибки.
4. Посмотри список доступных инструментов и групп. В текущем каталоге проекта инструменты вне `core` могут быть скрыты; `manage_tools(action="list_groups")` показывает группы, а `manage_tools(action="activate", group="...")` активирует группу, если эти действия доступны в установленной версии.
5. Если соединение нестабильно, проверь журнал MCP for Unity и перезапусти мост штатным способом из окна пакета.
6. Не редактируй вручную конфигурацию транспорта, если автонастройка уже работает, пока не зафиксировано конкретное несоответствие.

Для актуального HTTP-подключения документация проекта приводит `http://localhost:8080/mcp`. Порт `11434` — это Ollama API, а не Unity MCP. В конфигурации Cline это два разных соединения.

## 3. Ошибка с красным кубом

В предоставленном логе агент попытался назначить материал по пути:

`Assets/Materials/TestCubeMaterial.mat`

MCP вернул, что материал не найден. Это конкретно указывает на отсутствие найденного asset по указанному пути в момент вызова. Возможные причины: материал не был создан; путь неверен; AssetDatabase ещё не обновилась; инструмент работает с другим проектом/Unity instance; либо модель выбрала неправильный порядок действий.

### Правильная стратегия
1. Получить сведения о проекте и активной сцене.
2. Создать/найти `TestCube` и прочитать состояние объекта.
3. Посмотреть актуальную схему инструментов для материалов.
4. Если есть прямое действие установки цвета renderer, использовать его и подходящий режим.
5. Если прямого действия нет — создать материал подходящим для текущего render pipeline шейдером, проверить, что asset существует, затем назначить его.
6. Прочитать состояние объекта/renderer после операции и убедиться, что цвет действительно красный.
7. При ошибке не повторять тот же вызов; исправить путь, действие или способ создания ресурса.

### Пример из актуального каталога инструментов
В каталоге CoplayDev Unity MCP описан инструмент `manage_material` с действием `set_renderer_color`:

```json
{
  "action": "set_renderer_color",
  "target": "TestCube",
  "color": [1, 0, 0, 1],
  "mode": "create_unique"
}
```

`create_unique` предназначен для создания уникального сохраняемого материала для объекта в версиях, где такой режим доступен. Другие режимы могут иметь иную персистентность. Проверь текущую схему инструмента: документация предупреждает, что примеры могут отличаться в зависимости от версии и проекта.

Если установленная версия предлагает отдельный tool с именем `set_renderer_color`, а не `manage_material`, используй параметры именно из схемы этого tool. Не отправляй JSON, предназначенный для другого инструмента.

Альтернативный двухшаговый вариант, если прямое действие недоступно:
- `manage_material(action="create", material_path="Assets/Materials/TestCubeMaterial.mat", shader="<shader appropriate to render pipeline>", properties={...})`
- проверить существование материала
- `manage_material(action="assign_material_to_renderer", target="TestCube", material_path="Assets/Materials/TestCubeMaterial.mat", slot=0)`

Shader нельзя выбирать вслепую: для Built-in обычно используется `Standard`, для URP — `Universal Render Pipeline/Lit`, для HDRP — `HDRP/Lit`; сначала прочитай project info и сверяйся с установленными версиями.

## 4. Инструменты и группы

Используй `manage_tools(action="list_groups")`, если доступен, чтобы увидеть группы и их статус. В документации текущей ветки указаны группы `core`, `animation`, `asset_gen`, `docs`, `probuilder`, `profiling`, `scripting_ext`, `testing`, `ui`, `vfx`. Наличие группы в документации не гарантирует, что она доступна в установленной версии.

Важные возможности по каталогу:
- `manage_scene`: активная сцена, иерархия, сохранение и валидация.
- `manage_gameobject`: создание/изменение GameObject.
- `manage_material`: материалы и renderer color.
- `refresh_unity`: обновление AssetDatabase и запрос компиляции.
- `batch_execute`: пакетный вызов; не транзакционный, поэтому ранние команды не откатываются при поздней ошибке.

Проверяй фактические схемы инструментов, доступные текущему MCP-сеансу. Не делай вывод о версии пакета по одному названию инструмента.

## 5. Что собирать при повторной ошибке

- Версия Unity Editor.
- Версия пакета MCP for Unity из Package Manager.
- Статус подключения в Unity и Cline.
- Полное имя tool и его фактическая schema/parameters.
- Полные аргументы вызова, без секретов.
- Полный результат ошибки.
- Активная сцена и проект.
- Результат проверки, существует ли asset в Project window / через MCP.
