# 1. Ч что это за игра?

\*\*Angry Girls\*\* - это гибрид двух жанров:

┌─────────────────────────────────────────┐

│ 🎯 Запуск как в Angry Birds │

│ + │

│ ⚔️ Пошаговые атаки как в тактике │

│ + │

│ 🎒 Коллекционирование и прокачка │

└─────────────────────────────────────────┘

\*\*Коротко:\*\*

- Игрок запускает персонажей как снаряды

- В полёте или после приземления можно использовать уникальную способность

- После запуска всех персонажей начинается фаза поочерёдных атак

- Цель: убить всех врагов на всех стадиях уровня

- Между боями: прокачка, покупка снаряжения, выбор команды

\*\*Платформы:\*\* GDD заявляет Windows и Android, WebGL — возможная цель. Код содержит платформенные профили, но успешные сборки и совместимость не проверены.

\*\*Управление:\*\* Мышь (ПК) / Тап-свайп (мобильные)

\*\*Сессия:\*\* 5-15 минут на миссию

# 2. Быстрый старт: как играть

## 2.1 Первое, что видит игрок

\[Главное меню\]

├─ Новая игра → Выбор персонажей → Выбор миссии → БОЙ

├─ Продолжить → Загрузка сохранения → → Выбор персонажей → Выбор миссии → БОЙ

└─ Настройки → Громкость, камера, управление

## 2.2 Подготовка к бою

\*\*Экран подготовки миссии имеет 4 вкладки:\*\*

┌─────────────────────────────────────────┐

│ \[Персонажи\] \[Миссии\] \[Магазин\] \[Экипировка\] │

└─────────────────────────────────────────┘

| Вкладка            | Что делает игрок                                                                                 |
|--------------------|--------------------------------------------------------------------------------------------------|
| \*\*Персонажи\*\*  | Выбирает до 6 персонажей для команды. Персонажи выстраиваются в очередь запуска (слева направо). |
| \*\*Миссии\*\*     | Выбирает уровень и сложность (Легко/Нормально/Сложно). Видит награду за прохождение.             |
| \*\*Магазин\*\*    | Покупает снаряжение за кредиты. Ассортимент обновляется раз в 24 часа или за кредиты.            |
| \*\*Экипировка\*\* | Надевает оружие, броню, аксессуары на выбранных персонажей. Видит изменение статов.              |

## 2.3 Начало боя: что происходит

1\. Загружается сцена уровня

2\. Появляются персонажи игрока (в очереди запуска)

3\. Появляются враги на своих позициях

4\. Камера показывает поле боя

5\. Игрок может запустить первого персонажа в очереди

\*\*Важно:\*\* Запускать можно ТОЛЬКО самого правого персонажа в очереди (индекс 0). Чтобы запустить другого - нужно сначала поменять их местами через панель портретов.

# 3. Геймплей по шагам: полный цикл боя

## 3.1 Две основные фазы боя

┌─────────────────────────────────────────┐

│ БОЙ │

│ ┌─────────────┐ ┌─────────────┐ │

│ │ LAUNCH │ → │ ALTERNATE │ │

│ │ Запуск │ │ Атаки по очереди │ │

│ └─────────────┘ └─────────────┘ │

│ ↑ ↓ │

│ └────── цикл ──────┘ │

└─────────────────────────────────────────┘

### Фаза 1: Launch Phase (Запуск)

\*\*Что делает игрок:\*\*

1\. Зажимает ЛКМ/палец на персонаже в очереди

2\. Оттягивает в нужном направлении (как рогатку)

3\. Видит точки траектории полёта

4\. Отпускает → персонаж летит

5\. В полёте или после приземления может нажать кнопку для использования способности

\*\*Отмена запуска:\*\*

- Нажать ПКМ / второй палец

- Или оттянуть недостаточно далеко

\*\*После запуска:\*\*

- Персонаж исключается из очереди запуска

- Его портрет исчезает из панели снизу

- Камера следует за персонажем в полёте

### Фаза 2: Alternate Phase (Поочерёдные атаки)

\*\*Что происходит автоматически:\*\*

1\. Все живые ЗАПУЩЕННЫЕ персонажи игрока (кроме последнего запущенного) атакуют по очереди

2\. Затем все живые враги атакуют по очереди

3\. После этого - возврат в Launch Phase или конец боя

\*\*Пример с 3 персонажами:\*\*

Запуск 1: \[P1\] → летит, использует способность, заканчивает ход

Запуск 2: \[P2\] → летит, использует способность, заканчивает ход

↓ Переход в Alternate Phase ↓

Атаки: \[P1\] → \[Враг1\] → \[Враг2\] → \[Враг3\]

↓ Возврат в Launch Phase ↓

Запуск 3: \[P3\] → летит...

↓ Переход в Alternate Phase ↓

Атаки: \[P1\] → \[P2\] → \[Враг1\] → \[Враг2\] → \[Враг3\]

## 3.2 Окончание хода персонажа

\*\*Когда персонаж заканчивает ход:\*\*

| Тип персонажа       | Условие окончания хода                                           |
|---------------------|------------------------------------------------------------------|
| \*\*Ground\*\*      | Приземлился + прошёл таймер (~2-4 сек)                           |
| \*\*AirToGround\*\* | Приземлился + таймер ИЛИ использовал способность в воздухе       |
| \*\*Air\*\*         | Использовал способность ИЛИ приземлился (может висеть в воздухе) |

\*\*Важные нюансы:\*\*

- Если персонаж в воздухе и НЕ использовал способность - у игрока есть окно времени для активации

- После использования способности - ход заканчивается автоматически

- Получение урона персонажем должно вызвать завершение его хода.

## 3.3 Стадии внутри уровня

\*\*Уровень = одна или несколько стадий (Stage)\*\*

Уровень 0 (тестовый)

├─ Стадия 1: 3 врага на открытой местности

├─ Стадия 2: 5 врагов + препятствия

└─ Стадия 3: Босс + миньоны (планируется)

\*\*Что происходит при переходе между стадиями:\*\*

1\. Все выжившие персонажи игрока возвращаются в очередь запуска

2\. Их статы сохраняются (здоровье не восстанавливается автоматически)

3\. Спавнятся новые враги для следующей стадии

4\. Настраивается окружение (препятствия, бонусы)

5\. Обновляется очередь запуска в интерфейсе

\*\*Особенность логики запуска:\*\*

Если персонажей для запуска = 1:

\[Launch\] → \[Alternate\] → \[проверка победы\] → \[след. стадия или конец\]

Если персонажей для запуска \> 1:

\[Launch\] → \[Launch\] → \[Alternate\] → \[проверка\] → \[Launch\] → \[Alternate\] → ...

\> Первые два запуска подряд нужны, чтобы игрок мог быстро вывести в бой нескольких персонажей до начала ответных атак врагов.

## 3.4 Условия победы и поражения

ПОБЕДА если:

├─ Все враги убиты

└─ И (нет следующей стадии ИЛИ все стадии пройдены) ,

└─ И есть хоть 1 живой персонаж игрока

ПОРАЖЕНИЕ если:

├─ Все персонажи игрока запущены и закончили ходы

└─ И остались живые враги на текущей стадии

\*\*Особый случай:\*\*

\> Если последний запущенный персонаж убивает последнего врага СВОЕЙ атакой в Launch Phase - это победа (даже если не было Alternate Phase).

# 4. Персонажи: три типа и их особенности

## 4.1 Типы персонажей (UnitType)

┌─────────────────────────────────────────┐

│ 🟢 GROUND 🔵 AIRTOGROUND 🟡 AIR │

└─────────────────────────────────────────┘

### 🟢 Ground (Наземный)

\*\*Характеристики:\*\*

- Всегда заканчивает ход ТОЛЬКО на земле

- После использования способности в воздухе - его "тянет" вниз

- Не может использовать способность, если уже приземлился и таймер истёк

### 🔵 AirToGround (Воздушно-наземный)

\*\*Характеристики:\*\*

- Может закончить ход как на земле, так и в воздухе

- После способности в воздухе может:

- \- Задержаться в воздухе (инерция)

- \- Получить импульс вверх (отскок)

- \- Или упасть как Ground - зависит от анимации/настроек

- Способность НЕ обязательно заканчивается при приземлении

### 🟡 Air (Воздушный)

\*\*Характеристики:\*\*

- Может закончить ход в ЛЮБОМ месте (воздух/земля)

- После способности НЕ тянет к земле - остаётся на текущей высоте\*\*Тактическое применение:\*\*

## 4.2 Сравнительная таблица

| Характеристика                                  | Ground | AirToGround | Air         |
|-------------------------------------------------|--------|-------------|-------------|
| \*\*Окончание хода на земле\*\*                 | ✅ Да  | ✅ Да       | ✅ Возможно |
| \*\*Окончание хода в воздухе\*\*                | ❌ Нет | ❌ Нет      | ✅ Да       |
| \*\*Тянет к земле после способности\*\*         | ✅ Да  | ⚠️ Зависит  | ❌ Нет      |
| \*\*Может использовать способность на земле\*\* | ✅ Да  | ✅ Да       | ✅ Да       |

## 4.3 Как тип влияет на анимации и физику

\*\*Анимационные состояния:\*\*

- Idle (бездействие)

- Attack (атака)

- HitReaction (получение урона)

- Landing (приземление)

- Airboned (в воздухе)

- Death (смерть)

Каждый тип персонажа имеет свои правила переходов между этими состояниями.

# 5. Боевая система: фазы и логика ходов

## 5.1 Полный список фаз (GamePhaseNames)

1\. GameStartPhase - Инициализация боя (1 сек)

2\. StageSetupPhase - Спавн персонажей, настройка уровня (2-3 сек)

3\. LaunchPhase - Запуск персонажей игроком (10-30 сек)

4\. AlternatePhase - Поочерёдные атаки (30-60 сек)

5\. StageCompletePhase - Переход между стадиями (2 сек)

6\. VictoryPhase - Экран победы

7\. DefeatPhase - Экран поражения

\*\*Схема переходов:\*\*

GameStart → StageSetup → Launch → Alternate → \[StageComplete → StageSetup\] → ... → Victory/Defeat

↑\_\_\_\_\_\_\_\_\_\_\_↓

## 5.2 Детальная логика Alternate Phase

### 5.2.1 Построение очереди ходов

\*\*Алгоритм:\*\*

1\. Собрать всех живых персонажей (игрок + враги)

2\. Отфильтровать:

\- Враги: всегда в очереди

\- Игрок: только если ЗАПУЩЕН и НЕ является последним запущенным

3\. Отсортировать: сначала все игроки, потом все враги

4\. Выполнять по очереди

\*\*Пример данных:\*\*

Запущенные игроки: \[P1, P2, P3\] (P3 - последний)

Живые враги: \[E1, E2, E3\]

Очередь в Alternate:

\[P1\] → \[P2\] → \[E1\] → \[E2\] → \[E3\]

↑

P3 не атакует, т.к. только что закончил ход в Launch

### 5.2.2 Что делает юнит во время своего хода

\*\*Для персонажа игрока:\*\*

1\. Поворачивается к ближайшему врагу (в состоянии Idle)

2\. Использует базовую атаку (направленную вперёд)

3\. Ждёт окончания анимации атаки

4\. Устанавливает флаг: hasFinishedAlternateAttackTurn = true

5\. Переход к следующему в очереди

\*\*Для врага (AI):\*\*

1\. Поворачивается к ближайшему персонажу игрока

2\. Использует базовую атаку (направленную вперёд)

3\. Ждёт окончания анимации

4\. Устанавливает флаг завершения хода

5\. Переход к следующему

\> В текущей реализации враги не имеют уникальных способностей - только базовая атака "вперёд". Это запланировано к расширению.

### 5.2.3 Таймауты и защита от зависаний

\*\*Проблема:\*\*

\> Персонаж может "застрять" в анимации, не получить урон, не приземлиться - и фаза зависнет.

\*\*Решение (планируется):\*\*

Для каждого хода в Alternate Phase:

\- Запустить таймер (например, 10 секунд)

\- Если ход не завершился за это время:

\* Принудительно завершить ход персонажа

\* Логировать предупреждение

\* Перейти к следующему в очереди

\*\*Статус:\*\* В исходном GDD отмечено как не реализовано; в предоставленном дампе это требует отдельной проверки.

## 5.3 Использование способностей

### 5.3.1 Когда можно использовать

✅ Можно:

\- В полёте, после запуска, до приземления

\- Сразу после приземления, до окончания таймера

\- В фазе Alternate, во время своего хода (до атаки)

❌ Нельзя:

\- До запуска (персонаж ещё в очереди)

\- После окончания хода (флаги сброшены)

\- Если уже использовал в этом ходу (флаг hasUsedAbility = true)

### 5.3.2 Ограничения

| Ограничение                         | Реализация               | Статус                   |
|-------------------------------------|--------------------------|--------------------------|
| 1 способность на ход                | Флаг \`hasUsedAbility\`  | ✅ Реализовано           |
| Кулдаун между использованиями       | —                        | ❌ Не реализовано        |
| Энергия/мана для способностей       | —                        | ❌ Не реализовано        |
| Уникальные способности на персонажа | \`AttackAbilityManager\` | ⚠️ Частично (4 тестовые) |

### 5.3.3 Примеры тестовых способностей

| Название          | Тип              | Эффект                        | Визуал               |
|-------------------|------------------|-------------------------------|----------------------|
| \*\*Fireball\*\*  | Projectile       | Один снаряд вперёд            | Огненный шар         |
| \*\*HeadSpin\*\*  | Multi-Projectile | 6 снарядов веером             | Вращение + выстрелы  |
| \*\*SwordSpin\*\* | AoE              | Урон вокруг персонажа         | Вращение с мечом     |
| \*\*Uppercut\*\*  | Melee + Control  | Апперкот + заморозка анимации | Анимация удара снизу |

\> Эти способности - прототипы. Финальные способности будут привязаны к конкретным персонажам и иметь уникальный баланс.

## 8.2 Сохранения: что и как сохраняется

### 8.2.1 Что сохраняется

| Данные              | Где хранится                          | Как часто обновляется            |
|---------------------|---------------------------------------|----------------------------------|
| Кредиты             | Repository backend (требует проверки) | После каждой транзакции          |
| Прогресс миссий     | То же                                 | После завершения миссии          |

### 8.2.2 Как работает сохранение (упрощённо)

1\. Игрок выполняет действие (купил предмет)

2\. Менеджер предметов обновляет данные в памяти

3\. Менеджер сохранений получает уведомление об изменении

4\. Данные сериализуются в JSON

5\. JSON сохраняется в PlayerPrefs (локальное хранилище Unity)

6\. При загрузке: JSON читается и десериализуется обратно

\*\*Важно для тестировщиков:\*\*

\> Если после сохранения и перезагрузки данные "пропали" - проверьте:

\> - Не было ли ошибки сериализации (консоль Unity)

\> - Не изменилась ли структура данных в коде

\> - Не переполнился ли PlayerPrefs (лимит ~1МБ)

## 8.3 Оптимизация: пул объектов

\*\*Проблема:\*\*

\> Создание и уничтожение объектов (персонажи, снаряды, эффекты) в Unity - дорогая операция. При частых боях это вызывает лаги.

\*\*Решение:\*\*

Пул объектов (Object Pool):

1\. При старте игры создаётся "запас" объектов каждого типа

2\. Когда нужен персонаж - берётся из пула, а не создаётся новый

3\. Когда персонаж "умирает" - он не уничтожается, а возвращается в пул

4\. Следующий раз этот же объект будет использован снова

\*\*Что в пуле:\*\*

- Персонажи (игрок и враги)

- Снаряды (огненные шары и т.п.)

- Визуальные эффекты (цифры урона, монеты)

- Элементы интерфейса (слоты предметов)

## 8.4 Загрузка ассетов: Addressables

\*\*Проблема:\*\*

\> Если все персонажи, предметы и уровни загружать сразу - игра будет занимать гигабайты и долго запускаться.

\*\*Решение:\*\*

Addressables (система адресной загрузки):

1\. Каждый ассет (персонаж, предмет, иконка) имеет уникальный "адрес" (GUID)

2\. При необходимости игра запрашивает ассет по адресу

3\. Если ассет ещё не загружен - он загружается асинхронно

4\. После использования ассет можно "освободить" из памяти

\*\*Преимущества:\*\*

- Быстрый старт игры (загружается только необходимое)

- Экономия памяти (ненужные ассеты выгружаются)

- Возможность догружать контент "на лету" (для обновлений)

# 9. Детальные механики (из кода)

## 9.1 Физика и коллизии

### 9.1.1 Отталкивание персонажей (Repel)

Когда один персонаж приземляется на другово – он может выйти в состояние Idle и висеть на второ персонаже. Во избежание этого отталкиваем персонажа в сторону.

### 9.1.2 Coyote Time (Время койота)

\*\*Что это:\*\*

\> Буфер "приземления" после отрыва от земли (0.1 сек). Персонаж всё ещё считается на земле, даже если уже оторвался.

\*\*Зачем:\*\*

- Упрощает управление (игрок не наказан за минимальную задержку ввода)

- Позволяет использовать способности сразу после прыжка

\*\*Для тестировщика:\*\*

\> Если персонаж "не видит землю" сразу после отрыва - это может быть нормально в течение 0.1 сек.

### 9.1.3 Зоны мгновенной смерти (DeathZone)

\*\*Что это:\*\*

\> На уровнях есть триггеры, которые мгновенно убивают персонажа при касании.

\*\*Примеры использования:\*\*

- Пропасти

- Лава

- Шипы (планируется)

- Невидимые стены на краю карты

\*\*Важно:\*\*

\> DeathZone – убивает персонажа и завершает его ход..

## 9.2 Анимационная система

### 9.2.1 Машина анимационных состояний

\*\*6 фаз анимации:\*\*

1\. Idle - Бездействие

2\. Attack - Атака

3\. HitReaction - Получение урона

4\. Landing - Приземление

5\. Airboned - В воздухе

6\. Death - Смерть

\*\*Правила переходов:\*\*

- Каждый тип персонажа (Ground/Air/AirToGround) имеет свои правила

- Некоторые переходы запрещены (например, Air не может перейти в Landing)

### 9.2.2 Заморозка анимации

\*\*Что это:\*\*

\> Некоторые атаки (например, Uppercut) замораживают анимацию на определённом кадре (normalizedTime = 0.33) до приземления персонажа.

\*\*Зачем:\*\*

- Если поделить аниацию на 2, то выйдет анимация начала атаки в полете, и анимация завершения атаки (при контакте с землей), для чего придется реализовывать отдельную сложную логику (ранее была – отказался).

- Исходя из вышеописанного сперва идет апперкот, а при контакте землей добивание по земле

\> Персонаж "зависает" в верхней точке атаки, пока не начнёт падать.

### 9.2.3 Динамические коллайдеры

\*\*Что это:\*\*

\> BoxColliderUpdater меняет размер и позицию коллайдера в зависимости от текущей анимации.

\*\*Зачем:\*\*

- Точные хитбоксы для разных поз персонажа

- Предотвращает ложные попадания

\*\*Пример:\*\*

\> Когда персонаж приседает - коллайдер уменьшается. Когда атакует - увеличивается вперёд.

Стоит в будущем переделать текущую релизацию.

### 9.2.4 Синхронизация звука с анимацией

\*\*Как работает:\*\*

\> Звуки атак привязаны к конкретным процентам анимации.

\*\*Пример (SwordSpinAttack):\*\*

0% анимации → Звук начала атаки

50% анимации → Звук середины атаки

100% анимации → Звук окончания

\*\*Для аудио-дизайнера:\*\*

\> Если звук не синхронизирован с анимацией - проверьте массив \_soundTriggers в способности.

## 9.3 Камера

### 9.3.1 Ограничения камеры

| Параметр       | Значение                    |
|----------------|-----------------------------|
| Мин позиция Z  | -10                         |
| Макс позиция Z | 30                          |
| Мин зум        | 1 (ортографических единиц)  |
| Макс зум       | 10 (ортографических единиц) |

### 9.3.2 Тряска камеры

\*\*Когда происходит:\*\*

- При ударах снарядов

- При некоторых атаках (например, Uppercut)

- При смерти персонажа

\*\*Настройки:\*\*

- Длительность: 0.3 сек (по умолчанию)

- Амплитуда: 0.05 единиц

### 9.3.3 Зум после запуска

\*\*Что происходит:\*\*

\> Камера автоматически отдаляется после запуска персонажа.

\*\*Зачем:\*\*

- Игрок видит больше поля боя

- Легче отслеживать траекторию

\*\*Величина зума:\*\*

\> Ортографический размер уменьшается на (текущий размер / 6.1)

### 9.3.4 Следование за персонажем

\*\*Режимы:\*\*

1\. CameraFollowForRigidBody - центрирование по Y и Z координатам

2\. MoveCameraTo - плавное перемещение в точку

3\. Ручное управление - игрок перемещает камеру сам

\*\*Переключение:\*\*

\> Автоматически при запуске персонажа → следование. После окончания хода → ручное управление.

### 9.3.5 Убийство "двойников" камеры

\*\*Проблема:\*\*

\> При загрузке сцены могут оставаться старые камеры.

\*\*Решение:\*\*

\> KillCameraTwins() уничтожает все камеры кроме MainCamera при инициализации.

## 9.4 Визуальные эффекты (VFX)

### 9.4.1 Разделение VFX и Projectile

\*\*Важно:\*\*

\> VFXManager отвечает только за визуал, ProjectileManager - за физику и урон. Это разные системы.

### 9.4.2 Пул объектов по типам

\*\*Отдельные пулы:\*\*

- Персонажи (по CharacterType)

- VFX (по VFX_Type)

- UI объекты (по UIObjectType)

\*\*Преимущество:\*\*

\> Быстрый поиск и возврат объектов без перебора всех типов.

### 9.4.3 Всплывающие цифры урона

\*\*Как работает:\*\*

1\. При попадании снаряда создаётся TextMeshPro над точкой попадания

2\. Текст всплывает вверх (DOMoveY на 1 единицу за 1 сек)

3\. Через 1 сек объект возвращается в пул

\*\*Визуально:\*\*

\> Белые цифры, которые появляются и медленно плывут вверх.

### 9.4.4 Монеты с вращением

\*\*Анимация:\*\*

\> Coin.cs имеет анимацию вращения через DOTween

\*\*Параметры:\*\*

- Вектор вращения: (0, 180, 90)

- Длительность: 1 сек

- Циклы: бесконечно (пока не собрана)

### 9.4.5 Ready Banner

\*\*Что это:\*\*

\> Анимированный баннер "READY" с 3 стилями, вершинной деформацией, вспышками, частицами.

\*\*Стили:\*\*

Style1 - Базовый (вспышка + текст + свип)

Style2 - Радиальный взрыв + молнии

Style3 - Градиент + краевые бары + наклон текста

\*\*Использование:\*\*

\> Показывается при начале уровня (планируется).

\*\*Параметры:\*\*

\*\*Пример:\*\*

### 9.5.4 Переопределение громкости на клип

\*\*Зачем:\*\*

\*\*Важно:\*\*

# 10. Частые вопросы и ответы

## ❓ Почему в Alternate Phase последний запущенный персонаж не атакует?

\*\*Ответ:\*\* Потому что он только что закончил свой ход в фазе запуска. Давать ему два хода подряд нарушило бы баланс. Это сознательное дизайнерское решение, а не баг.

## ❓ Почему персонаж типа Air может "висеть" в воздухе, а Ground - нет?

\*\*Ответ:\*\* Это различие в геймплейной роли:

- Ground - надёжный, предсказуемый, для новичков

- Air - мобильный, сложный, для продвинутых игроков

В исходниках есть отдельные правила \`UnitType\` и логика в \`CControl\`/\`CharacterMovement\`; утверждение про конкретный флаг \`isKinematic\` и метод \`FinishTurn()\` не считать подтверждённым без сверки текущей реализации.

## ❓ Что будет, если все враги убиты в середине Alternate Phase?

\*\*Ответ:\*\* Бой немедленно завершается победой (если это последняя стадия) или переходит к следующей стадии. Оставшиеся в очереди юниты не получают ход - это оптимизация.

## ❓ Можно ли использовать способность, если персонаж уже приземлился?

\*\*Ответ:\*\* Да, но только если:

- Это фаза Launch или Alternate

- Персонаж ещё не использовал способность в этом ходу (\`hasUsedAbility == false\`)

- Не истёк таймер после приземления (для типов Ground/AirToGround)

## ❓ Почему в магазине иногда нет предметов нужной редкости?

\*\*Ответ:\*\* Ассортимент генерируется случайно из доступных коллекций. Если коллекция ещё не открыта (по прогрессу) или в ней закончились предметы - их не будет в ассортименте. Обновите магазин или пройдите больше миссий.

## ❓ Что происходит с экипировкой, если персонаж умирает в бою?

\*\*Ответ:\*\* Ничего. Экипировка сохраняется. В следующем бою (или стадии) персонаж будет с тем же снаряжением. Смерть в бою - это тактический проигрыш, а не потеря прогресса.

## ❓ Как добавить нового персонажа в игру?

\*\*Краткий чеклист:\*\*

1\. Создать префаб персонажа с анимациями и коллайдерами

2\. Создать \`CharacterSettings\` (ScriptableObject) с параметрами: тип, статы, анимации

3\. Добавить тип в \`CharacterType\` enum

4\. Добавить запись в \`CharacterFactory\` для загрузки префаба

5\. Добавить в \`CharacterSettingsCatalogSO\` для доступа из игры

6\. Протестировать в бою с разными типами врагов и окружением

\> Детали - в техническом GDD, раздел "Добавление контента".

## ❓ Что такое Coyote Time и зачем он нужен?

\*\*Ответ:\*\* Это буфер времени (0.1 сек), в течение которого персонаж считается "на земле" после фактического отрыва. Это упрощает управление - игрок не наказан за минимальную задержку ввода при прыжке или использовании способности.

## ❓ Почему камера иногда "дёргается"?

\*\*Ответ:\*\* Возможные причины:

1\. Тряска камеры при ударах (нормально)

2\. Переключение между режимами следования и ручного управления

3\. Конфликт нескольких камер в сцене (баг, должно быть уничтожено KillCameraTwins)

## ❓ Как работает система отталкивания персонажей?

\*\*Ответ:\*\* Когда два персонажа сталкиваются в воздухе (не союзники), они отталкиваются друг от друга на 0.4 единицы за кадр. Это предотвращает застревание и создаёт тактические возможности.

# Приложение B. Заметки по соответствию коду (редакция 3.0)

## Инициализация

Bootstrap проверяет CoreManager, создаёт GameStateManager при отсутствии, вызывает InitializeSystemsAsync и затем загружает MainMenuScene. CoreManager сохраняется между сценами через DontDestroyOnLoad.

## Gameplay systems

GameplayCoreManager инициализирует InputManager, CameraManager, GameLogic, GamePhaseFlowController, GameplayCharactersManager, StageManager, LaunchManager, TurnManager, HealthBarManager, TurnOrderService, InteractionManager, ProjectileManager и AttackAbilityManager.

## Способности

AttackAbilityManager использует Resources.LoadAll\<AttackAbilityData\>("AttackAbilitiesTemplates") и связывает Fireball, SwordSpin, HeadSpin и Uppercut. Наличие и корректность данных в Resources нужно проверить в проекте.

## Ввод

InputManager выбирает TouchInput на мобильных платформах и MouseInput в остальных случаях; код использует legacy UnityEngine.Input. Переход на новый Input System не описан и потребует отдельной миграции.

## Сохранение

SaveLoadManager регистрирует менеджеры персонажей, кредитов, миссий, магазина и инвентаря и делегирует сохранение Repository. Не считать PlayerPrefs/JSON фактом до проверки backend в Repository.cs.

## Известные риски

Временная загрузка оружия, условие в BoxColliderUpdater, возможная потеря полей InventoryItem при загрузке, ожидания завершения хода без очевидной гарантии таймаута и чувствительность к сериализованным ссылкам требуют отдельных задач и runtime-проверки.

## Что отсутствует для окончательной верификации

Полный Unity-проект: сцены, префабы, ScriptableObjects, .meta, ProjectSettings, Packages/manifest.json, Build Profiles, .asmdef, тесты и результаты сборки.
